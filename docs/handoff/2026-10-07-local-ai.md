# Local AI, phase 1: the on-device model by default (2026-10-07)

Branch `wt/ai` (worktree of the 2026-10-07 batch). Plan `local-ai` option A, with the owner's decisions:
Hoa has an iPhone 16 Pro (Apple Intelligence capable), so the system's on-device model can run every AI feature.
Phase 2 (a downloadable Core ML model, off by default) is a separate stage and is **not** in this branch.

## What changed

- **On-device is the default.** `AISettings.provider` defaults to `ON_DEVICE` (Android: `GEMINI`). A user who had
  Gemini selected without a Gemini key is moved to on-device once at launch (`ai_provider_migrated_v1`), and again
  after a settings restore (an Android backup can bring GEMINI back; with its key, Gemini stays).
- **No cloud fallback.** An on-device selection only ever tries the on-device model (PixlNet `AiOrchestrator` takes a
  `providerChain`; the app passes `[ON_DEVICE]` for on-device, Android's chain for cloud selections).
- **Cloud is optional.** Settings › AI features: the on-device model row first ("in use", or why it can't be used),
  then "Cloud assistants (optional)" with a "Use a cloud assistant" switch, off by default, that reveals the provider
  picker, Save on usage, sign-in, model and base URL. Advanced shows only Temperature on-device.
- **"No Internet Connection" bug fixed.** Every on-device failure used to read "No Internet Connection" (the provider
  was named "On-Device (Offline)" and the error rules match "offline"). On-device failures now have their own messages
  (too long, safety filters, language, still downloading, busy, slow, not on this iPhone, turned off) and the playlist
  error table checks them first. iOS 27's new Foundation Models error types are mapped too (in `Compat27`).
- **Each feature has an on-device path sized for the 4,096-token window:**
  - AI playlist sheet, AI Playlist Lab, Daily Mix refine → `OnDevicePlaylistCurator`: songs the request names, then the
    day's picks; one numbered line per song (no ids reach the model); the model can only answer valid numbers;
    the pool shrinks until it fits. Lab requests over 40 songs: the model plans (genres and artists from the library's
    own values, moods, energy, familiar or not), the app fills the playlist, the model orders the first 40.
  - Taizo → one conversation that remembers what was said, a `searchLibrary` tool for questions about the user's own
    music, and the queue card's intro line arrives just after the card instead of holding it back.
  - "Translate via AI" (long-press in the lyrics More sheet; the lyrics UI itself is the lyrics group's) → each
    distinct line is translated once, in chunks; the stored LRC is the same as the cloud path's.
  - Home → Android's AI greeting is ported: one AI headline a day and the longer insight when the card is expanded
    (a small spinner while it is written).
- The models are prewarmed when the Taizo, AI playlist and Lab sheets open.

## How it was verified (no Mac here)

- `swift build` + `swift test --filter` of PixlCore on Linux (Swift 6.4): the AI tests pass, including the new
  `customProviderChainKeepsOnDeviceRequestsLocal`.
- The pure on-device files (`OnDevicePrompts`, `OnDeviceCuration`, `OnDeviceLyricsTranslation`, `AILyricsTranslator`,
  `TaisDjEngine`, `TaisChatModel`, `HomeLogic`) compiled on Linux in Swift 6 mode with MainActor default isolation,
  and `AppTests/OnDeviceAITests` (17 tests) passed there against stand-ins for the model.
- `OnDeviceAI`, `OnDeviceModel` and `OnDeviceAiClient` type-checked on Linux against a stand-in Foundation Models
  module written from the developer.apple.com declarations (macros stripped). `HomeStore`, `AISettings`,
  `AISettingsBridge` and `AIProviderStatus` type-checked with small stubs for the rest of the app.
- Every changed file passes `swiftc -parse`; `ci/check-forbidden.sh` is clean.
- **Not compiled yet:** the SwiftUI views (`AISettingsSection`, `HomeSections`, `LibrarySheets`, the AI sheets),
  `AIService`, `AppEnvironment`, `HomeAIGreeter`, `Compat27` (iOS 27 types) and the real Foundation Models SDK. CI
  compiles them after integration. The likeliest compile questions: the `String` overload of
  `respond(to:schema:options:)`, `Instructions { text }` in `tokenCount(for:)`, and `LibraryLookupTool`'s `Tool`
  conformance under the iOS 27 SDK.

## For phase 2 (the downloadable model)

The on-device features reach the model through seams a Core ML backend can fill without touching the features:
`OnDevicePlaylistCurator.Model` (pick / plan / text closures), `TaizoOnDevice` (chat, intro), `OnDeviceLyricsTranslator`
(`respond`) and `HomeAIGreeter.greet`. `OnDeviceContext.isActive()` is where "Use downloaded AI model" would choose.
