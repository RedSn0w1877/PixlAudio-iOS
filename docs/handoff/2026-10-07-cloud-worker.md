# Cloud Studio part 1: the RunPod worker and its workflows (2026-10-07)

Branch `s19-cloud-worker`. Design: `docs/handoff/2026-10-07-plans/cloud-studio-design.md` sections 2–3 with every
"(revised)" change and the Review notes. Owner decisions: `DECISIONS.md › Cloud Studio` (R2 with presigned URLs,
no Whisper in v1, anvuew ft1, transcribe songs without lyrics as "AI-written lyrics", instrumental + word-timed
lyrics, $10 prepaid / max 1 worker / $2-a-week alarm). Only `cloud/runpod-worker/`, three new
`.github/workflows/cloud-worker-*.yml` files, the `ci.yml` paths-ignore line, `docs/parity.md` and
`docs/test-parity.md` changed. No app code, no Swift. **Nothing was deployed, no RunPod or Cloudflare call was
made with a key, and no money was spent.**

## What changed

1. **The worker** (`cloud/runpod-worker/src/pixl_worker/`): one RunPod handler for `op: process | selftest | bench`.
   - Schema v1 validation by hand (stdlib) and the golden examples (`schema/v1/`), which the app's tests will
     decode; a CI step (`ci/check_fixtures.py`) fails once the app's copies drift.
   - Storage through presigned R2 URLs only (the worker holds no credentials): HTTPS, the host must be
     `<R2_ACCOUNT_ID>.r2.cloudflarestorage.com` (set by the deploy from the GitHub variable), public resolved IP
     pinned for the connection, SigV4 signature present, the URL must point at this job's own object, no
     redirects, streamed byte cap and sha256 check, retries with backoff for 5xx/429/timeouts only. The RunPod
     network-volume fallback is kept.
   - **Input cap 160 MB** (agreed with the app side: a 15-minute song decoded to FLAC on the phone is ~90–130 MB).
     The download's time budget scales with the size (120 s + 1 s per 2 MB) and covers all retries together.
   - Guard (design 2.3): a finished manifest for the same input is returned at once (`warnings: ["duplicate"]`); a
     third delivery of the same RunPod job is refused with `POISONED` and an error manifest.
   - Pipeline: ffprobe on the local file (format/codec allowlists, cover art ignored, other video refused) →
     ffmpeg decode → BS-RoFormer anvuew ft1 (msst, overlap 2, or 4 for "best" up to 8 min) → optional
     htdemucs_ft → lyrics → AAC 256k `+faststart` or FLAC → uploads → `manifest.json` last → delete the input
     only after `ok`/`partial`. Every output keeps the input's sample rate and frame count.
   - Lyrics: global offset check (spoken intros), one window per line, Qwen3-ForcedAligner for its 11 languages,
     UTF-16 `c0/c1` offsets so the app rebuilds words exactly, line timing as the fallback. **No Whisper**: other
     languages get line timing; `WordTimingBackend` + `register_backend()` is the hook for adding it later.
     Songs without lyrics: Qwen3-ASR (loaded on first use) → `mode: "transcribed"` (the app shows "AI-written
     lyrics"). New: in a Vietnamese song, a plain-ASCII line (an English hook) gets word timing as English.
   - New: a job that **fails validation** still gets an error manifest when its own manifest URL passes every
     check, so a phone collecting from R2 later doesn't take it for "lost" and resubmit it forever.
   - New: the selftest reports the server caps (`caps.maxInputMB`, `hostsConfigured`, ...); the deploy fails if
     the host allowlist is empty.
   - JSON-lines logs with redaction (URLs as host/path, no `X-Amz-*`, no lyrics or bodies); the RunPod SDK's own
     log level is set to INFO.
2. **The image** (`Dockerfile`): stages `test | deps | small | final | smoke`.
   - Every `FROM` and the frontend pinned by digest (`pytorch/pytorch:2.11.0-cuda12.8-cudnn9-runtime@sha256:eee1…`,
     `python:3.12-slim@sha256:05cd…`, `docker/dockerfile:1.10@sha256:865e…`).
   - Every large weight is its own `ADD --link --chmod=644 --checksum=sha256:…` layer from a pinned URL
     (HF commit revisions; demucs content-addressed names), listed with size, sha256 and licence in
     `weights.lock`. All sha256 were verified on 2026-10-07 (HF LFS hashes from the API; the small files and
     the four demucs files downloaded and hashed). `ci/check_weights.py` fails on any disagreement, an unpinned
     `FROM`, a `main` revision, or a `RUN` in the final stage.
   - Python: `requirements.in` → `requirements.lock` (≈150 packages, hashed, generated by `ci/lock.py` with uv for
     CPython 3.12 / manylinux_2_39, constrained to the base image's own torch stack, which is left out of the lock).
     Installed with `pip install --no-deps --require-hashes`; qwen-asr without its demo-app deps;
     `ci/pip_check.py` fails on any new conflict. The base's `spin` dev tool is removed (it pins `click<8.4`,
     runpod needs ≥ 8.4.2).
   - `smoke` (CI only): loads the real BS-RoFormer, aligner and htdemucs_ft weights **on CPU** and runs each once,
     so a dependency/weights mismatch shows up on free CI rather than on Hoa's balance. ASR is left to `bench`.
3. **Workflows** (actions pinned to commit SHAs: checkout v7.0.1, setup-buildx v4.4.1, login v4.6.0,
   build-push v7.4.0):
   - `cloud-worker-build`: tests on every worker change; on main builds and pushes `…:sha-<12>` and `…:main`
     (gzip level 1, inline cache); on any other branch builds without pushing (plus the smoke stage) when the
     commit message says `[image]`.
   - `cloud-worker-deploy` (`environment: runpod`): after each green main build it updates an **existing**
     endpoint; the first deploy is by hand (Run workflow) and creates it. `deploy/runpod_deploy.py` (stdlib,
     REST v2): anonymous GHCR pull check, create or minimal PATCH (complete env, pools with exclusions), rollout
     wait, selftest until this build's gitSha answers, optional bench + W1 concurrency check.
   - `cloud-worker-keepalive` (daily 06:17 UTC): restores `workers.max` after RunPod's idle scale-down, but never
     while workers are unhealthy or after a failed deploy; fails (email) when 7 days cost more than
     `CLOUD_WEEKLY_ALARM_USD`. Sends no jobs. Before setup it just succeeds.
   - Public logs: no keys, no endpoint id (masked), no response bodies, no money.
4. **Docs**: `cloud/runpod-worker/README.md` (how it works, cost, owner checklist, runbook), `NOTICE` +
   `LICENSES/` (GPL-3.0 for the anvuew checkpoint and Ubuntu's ffmpeg, GPL-2.0/LGPL-2.1 for ffmpeg, Apache-2.0
   for Qwen, MIT for msst/demucs/runpod), `docs/parity.md` (iOS first, Android later), `docs/test-parity.md`.

## Deviations from the design

- **No package pruning** step in the build: public GHCR storage is free and layers are shared, and an automatic
  prune risks deleting the tag the endpoint runs. Prune by hand if it ever matters.
- **Auto-deploy only updates.** The design's `workflow_run` deploy would also create the endpoint; here the first
  deploy is always by hand (owner step B4), so the first main build doesn't fail before the package is public.
- **Transcription uses VAD phrases of ≤ 12 s** (one line each) instead of 180 s chunks, so every transcribed line
  gets its own timing.
- **Input cap 160 MB** instead of 60 MB (the app uploads FLAC for anything that isn't AAC-LC M4A).
- Added: the CPU smoke stage, the rejection manifest, `caps` in the selftest.

## Review (adversarial pass, same day)

Fixed on the branch after the implementer finished:

- **A lyrics-only job whose lyrics fail is now an error, not `partial`.** A song that already has its
  instrumental sends `tasks: ["lyrics"]`; before, a lyrics failure there returned `partial` with no outputs and
  deleted the input, so the phone had to upload again to retry. Now it fails with the lyrics' own code (or
  `INTERNAL`), writes the error manifest and keeps the input. With stems requested it stays `partial`, and the
  warning names what was kept ("the instrumental is complete" / "the other outputs are complete").
- **176.4/192 kHz input with AAC output fails before the separation.** ffmpeg's AAC encoder silently resamples to
  96 kHz (checked with ffmpeg), so the manifest's sample rate and count would have been wrong and the phone would
  have rejected the stem after a billed separation. It now fails `UNSUPPORTED_FORMAT` ("ask for flac output")
  right after the probe; FLAC output keeps 192 kHz (test).
- **By-hand deploy with an empty `image_tag` deploys the newest green main build.** Before, it deployed
  `sha-<the main commit it ran on>`, which doesn't exist whenever an app-only commit landed on main after the
  last worker build (very likely with the batch merging), and the error blamed package visibility.
- **The deploy cancels jobs it stops waiting for** (selftest, bench, the 3 concurrency jobs) when no GPU turns up
  within its timeout, so they can't start and bill later.
- The storage transport tries every resolved public address in order (an unreachable IPv6 address on a host
  without IPv6 routing no longer fails the download); `cloud-worker-build` no longer runs on tag pushes (path
  filters don't apply to tags).

Checked and left as is: the RunPod REST v2 field names and shapes against the live OpenAPI spec (create/update,
`pools` + `excludedTypes`, releases' `rollout`, workers' `summary`, billing totals, list pagination); msst's chunk
loop really calls the progress hook (`pbar=detailed_progress`); qwen-asr's `transcribe(audio, language=)` and
result fields; the runpod SDK pops `error`/`refresh_worker` and logs job outputs only at DEBUG (the image sets
`RUNPOD_LOG_LEVEL=INFO`). No app code changed on this branch, so there are no screenshots to look at.
