# Equalizer, lyric offsets and automatic track changes

The iOS and Android changes use separate `fix-eq-timing` branches. Both equalizers put the
power control, presets, ten frequency bands and audio effects in the same order. On iOS, the
processing tap now follows the sample rate of each prepared item, including during a transition.
Preset edits and saved effect settings survive bypassing the EQ.

In Lyrics → More → Adjust sync, the four step buttons and the reset value share one glass capsule.
The strip stays visible while adjusting. The karaoke clock applies an intentional backward nudge
on the next frame, and switching songs loads the saved offset for that song.

Catalog streams with inflated durations now use the scrubber's endpoint in the deck, scheduler and
system Now Playing metadata. Now Playing pauses its clock during a stall and a failed preroll falls
back to natural queue advance. Imported files continue using the file's actual duration.

The branch CI builds the iPhone app and unsigned IPA. Regression coverage includes a 12-second
rendition of a six-second catalog song, the change to the next track, editing an EQ across
44.1 and 48 kHz taps, and using each visible lyric offset control. See the pull request for
verification results. On iPhone, compare the player and Lock Screen durations on a previously
affected song, let it advance, then open Adjust sync and tap each step and reset.

## Port onto new-ui (branch `new-ui-eq-timing`)

Cherry-picked 152580f and ec56f0c from `fix-eq-timing` (PR 35, untouched) onto `new-ui`. Both applied without
textual conflicts (`LyricsChrome.swift`, `docs/design.md`, `docs/parity.md`, `docs/api-notes.md` auto-merged: the
fix touched `LyricsControlCluster` and `LyricsSyncControls`, new-ui rewrote `LyricsToolbar` and the segment
views, so the hunks did not overlap). Both sets of changes are kept.

Conformed to the new design: the timing-offset row (`LyricsSyncControls`) was a full-width capsule of
filled 44 pt buttons in `labelLarge`; it now matches the new pill toolbar (`Tokens.PlayerPills` capsule, 64 pt,
5 pt inset, 4 pt spacing, 54 pt segments, `bodyMedium` bold, interactive clear glass, press scale 0.94 like the
options segment). The fix's accessibility labels and identifiers, equal columns, full-height tap targets and
Reduce Motion handling are unchanged (materialize is skipped under Reduce Motion). The equalizer and settings
screens are untouched by the redesign and keep the fix's UI; they already use the shared `GlassCircleButton`,
`pixlGlass`, `PressScaleButtonStyle` and `GlassPillRow`.

Unverified on a device: the new row's look and height with the cluster (three 64 pt bands), the materialize
animation, and everything in the fix's own list above. Only PixlCore compiles on the Windows machine; `App/`
compiles in CI.
