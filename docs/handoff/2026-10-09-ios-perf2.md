# iOS performance round 2 (2026-10-09, branch `perf2-ios-oct9`)

Round 2 of the speed work. Look and behaviour are meant to be identical. There is no Mac and no phone in the loop, so
none of this is measured on a device: the notes say what work the code now avoids. Tests were added where cheap.

## Done, item by item

1. **Home scroll threshold** (`ios-home-search-1`). The "scrolled past 110 pt" flag lives in a small `@Observable`
   (`HomeScrollState`, like Stats' collapse state) read only by the top bar. Crossing the threshold re-renders the bar,
   not Home's body and every section.
2. **Home recomputation** (`ios-home-search-2`, partly). A superseded computation now stops at the next stage
   (`HomeStore.computeIfActive`; before, only a wrapper was cancelled). A refresh caused only by a finished song waits
   1.5 s (after the skip and the re-theme) and runs at utility priority; library, day, taste changes and the refresh
   button stay immediate. Home keys on a new `LibraryStore.songsRevision`, which artist-picture batches do not bump.
3. **Artist pictures** (`ios-launch-artist-batch-revisions`). Found pictures reach the library at most every 2 s and
   are written to the cache once; the detail index is carried over (re-stamped) because songs did not change.
4. **Library lists** (`ios-library-2` / `ios-data-revision-fanout`). `LibraryModel.compute` reuses each list when its
   inputs are equal (playlist edit re-sorts only playlists, picture update only artists). A heart tap changes one
   field no sort reads, so sorted lists, folder tree and folder views are patched by id. The detail index is patched
   off the main actor too. `LibraryModelPatchTests` proves patched lists equal fresh ones (hearts, playlist rename,
   picture, a title edit that must fall back) for the All and Offline filters; a second test does the same for the index.
5. **Catalogue play/like** (`ios-data-remote-import-full-reload`, partly). A one-track import no longer reloads the
   whole library twice (the flush reload is skipped, the final one stays). YouTube Music import patches lookups
   (`applyEdit` with added album/artist) instead of comparing the library (`ios-data-youtube-import-main`,
   `ios-library-8`).
6. **Play queue** (`ios-launch-queue-userdefaults`, `ios-data-queue-userdefaults`, `ios-playback-3`). The queue
   snapshot lives in `Application Support/playback_queue_snapshot_v1.json`, written off the main actor with a save
   number so an older write never wins; the old UserDefaults value is migrated once and removed. Termination still
   saves synchronously.
7. **AI headline** (`ios-launch-ai-greeting-model`, `ios-home-search-8`). The daily headline request waits 8 s, so the
   model does not load during launch.
8. **Listening history** (`ios-data-history-rewrite`, `ios-playback-4`, `ios-home-search-5`, partly). The history file
   is rewritten once per 3 s of changes, immediately on import/clear and when the app goes to the background.
9. **Detail headers** (`ios-library-6`): the scroll offset stops at 300 pt, so collapsed headers stop re-rendering per frame.
10. **Album cards** (`ios-library-5`): no second render of every card when the colours are already cached.
11. **Playlist page** (`ios-library-10`): lyric-sync progress re-renders only its card; equal progress is not re-published.
12. **Song pickers** (`ios-library-9`): a new keystroke cancels the old filter pass (stops within 256 songs).
13. **Search genres** (`ios-home-search-7`, partly): each genre hashed once; list replaced only when changed.

## Skipped, and why

- `ios-launch-init-blocking`, `ios-playback-5/8`: moving the audio session set-up and the SwiftData container off
  `init` changes the order of things the audio session and every store rely on; cannot be checked without a device.
- `ios-data-remote-import-full-reload` incremental apply-from-store: needs a new persistence fetch path; only the
  duplicate reload was removed.
- `ios-home-search-2` memoising library-only parts and a rankings-only summary: larger rewrite of stats code.
- `ios-home-search-9` (GlassEffectContainer for pills/shelves): can change how glass looks and presses.
- `ios-player-6` (pre-warm timing): the pre-warm has a history of a stuck-player bug; not touched.
- `ios-player-7` (pressed lyric row): property-level observation re-renders every row reading it anyway; no gain.
- `ios-player-5` (lyrics piece tables, flat Text interpolation): could change glyph runs of the loved lyrics view.
- `ios-images-6` (write thumbnails after returning): tests and the second disk tier read files right after a load.
- `ios-playback-7/9/10/11`, `ios-data-cache-writes`, `ios-data-persistence-contention`, `ios-images-3/5/7/8/9`,
  `ios-library-4/7/11/12`, `ios-player-2/3/4`, `ios-launch-shell-body/measure`: not done in this round (risk or size);
  see the audit journal.
- Lyrics/AI/Settings pass (`ios-lyrics-ai-settings`): grepped for main-thread file IO, decoders and timelines. File
  scans are already detached, timelines pause when idle, settings sheets keep work in tasks. Nothing clearly wrong to fix.

## Behaviour to notice

- Recently Played / the stats card refresh about 1.5 s after a song ends instead of at once.
- Artist pictures appear in groups every ~2 s.
- The AI headline arrives 8 s later at the earliest.
- A hard kill within 3 s of a song change can lose that one history entry.
